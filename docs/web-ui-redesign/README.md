# 웹 UI 개편: 정보 구조와 디자인 규칙

브랜치 `feature/web-ui-korean-redesign` (기준: master `625c049`). 웹 소스(`frontend/`)의 디자인·메뉴 구조·표시 문구만 바뀌었다.
백엔드 API, DB 스키마, 권한, route, 업무 기능은 바꾸지 않았다.

### 결정이 필요한 항목 (임의로 합치지 않음)
- **대시보드 / 운영 현황**: 서로 다른 화면(경영 지표 vs 실패 작업·연동 상태)이라 합치지 않았다.
- **보고서 / 매출·손익 분석**: 역할이 일부 겹치지만 별도 기능이라 유지했다.
- **보고서 예약의 "보고서 종류 코드"**: 서버가 자유 문자열로 받으므로 입력 칸을 그대로 두었다(목록에서는 코드값이 보인다).
- 채널(쇼핑몰)이 보낸 고유 주문 상태 문자열은 운영자가 채널 화면과 대조해야 하므로 원문을 그대로 보여 준다(내부 상태와 같은 값만 한국어로 바꿈).

## 2. 한국어 표시 규칙 (단일 출처: `frontend/src/labels.ts`)
- 내부 값(enum)과 API 값은 바꾸지 않는다. 화면 표시만 `label(도메인, 값)`으로 바꾼다.
- 알 수 없는 값은 코드를 보여 주지 않고 `알 수 없음`으로 표시한다.
- 같은 상태는 모든 화면에서 같은 문구(예: 명령 상태, 교환·반품·취소 처리 상태, 동기화 결과).
- 동기화 결과의 `PARTIAL`(클레임·정산)과 `PARTIAL_SUCCESS`(CS 동기화)는 둘 다 "일부 완료"로 표시한다. 백엔드의 두 값은 서로 다른 계약이므로 하나로 바꾸지 않았다.
- 서버 오류 문구는 한국어일 때만 그대로 보여 주고, 영어·개발자용 문구와 검증 오류 배열은 상태 코드별 안전한 한국어 문구로 바꾼다. 응답 본문, URL, 상태 코드 숫자는 화면에 내지 않는다.

## 3. 디자인 토큰 (`frontend/src/styles/tokens.css`)
흰색·검정·회색만 쓴다. 색상값은 이 파일에만 있고 화면 CSS와 TSX는 변수만 쓴다(테스트가 검사).

| 용도 | 라이트 | 다크 |
|---|---|---|
| 페이지 배경 | `#FFFFFF` | `#111111` |
| 보조 배경 | `#F7F7F7` | `#1A1A1A` |
| 주요 텍스트 | `#111111` | `#F2F2F2` |
| 보조 텍스트 | `#666666` | `#A8A8A8` |
| 비활성 텍스트 | `#999999` | `#777777` |
| 기본 / 강한 테두리 | `#E5E5E5` / `#CFCFCF` | `#2E2E2E` / `#454545` |
| 주요 버튼 | `#111111` 바탕, `#FFFFFF` 글자 | 반전 |
| hover / 선택 | `#F1F1F1` / `#EAEAEA` | `#222222` / `#2C2C2C` |

- 반경 6/8/10px 토큰, 그라데이션·바깥 그림자 없음(현재 위치 표시용 왼쪽 inset 선만 허용).
- 성공·경고·오류는 색이 아니라 기호(✓ ! ✕ ● ○), 테두리 모양(실선/점선), 굵기, 반전 바탕으로 구분한다. 흑백에서도 구분된다.
- 모든 키보드 초점에 2px 윤곽선(제거 금지), 아이콘은 SVG 한 종류, 아이콘 전용 버튼에는 `aria-label`.
- 다크 화면(사용자 설정 `theme_preference`)은 기존 기능이라 유지했고 같은 토큰으로 반전한다.
